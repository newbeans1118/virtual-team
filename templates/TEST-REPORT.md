# 测试报告（RPT）——骨架生成 + 人工结论

> 模版：TEST-REPORT.md ｜ 生成骨架：`python scripts/gen_docs.py --root . --type report [--run RUN-xxx]` ｜ 存放：`test/report/RPT-<RUN>.md` ｜ 完成责任：test-engineer
> **分工**：数字段（计划/执行/通过/失败/阻塞、未关闭 P0/P1）由脚本填入并指向 `test-metrics-<RUN>.md`；**叙事与结论必须人工写**，脚本不代写。

## 1. 生成规则

- 骨架只生成一次：文件已存在时脚本**跳过**（`--force` 才覆盖，会丢失人工段落）。
- 三处 `<!-- 待填 -->` 未清空 = 报告未完成，不得交 test-manager 审定：
  1. §2 执行摘要（一段话说明本轮测了什么、结论倾向）；
  2. §4 遗留问题（P2 / 已知限制 / 环境风险，P0/P1 已自动列）；
  3. §5 结论（通过 / 不通过 + 建议）。
- **数字不得手抄**：§2 只允许一行摘要 + 指向 test-metrics 的章节号；抄录即制造第二个数字源。

## 2. 结论依据（缺一不成立）

| 依据 | 出处 | 判定 |
|------|------|------|
| P0/P1 遗留 | `test/bugs/BUG-*.json` 状态机 | 有未关闭 → 不通过 |
| 覆盖缺口 | `test-metrics` §3 | 缺口项须逐条给「接受 / 不接受」判断 |
| 执行完整性 | `test-metrics` §1 | 执行率 < 100% 须说明原因 |
| NFR | `test/nfr/report/NFR-RPT-*.md` | 参考件，不改结论，但核心项未达标须列为风险 |

## 3. 红线

- 不得把「未执行」写成「通过」（证据先于结论，discipline §1）。
- 不得在同一份报告里重算覆盖率——数字冲突时以 `test-metrics` 为准并重跑生成。
