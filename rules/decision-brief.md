# 决策简报格式（Decision Brief）

本文件规定**向用户提问 / 请求决策时的最小格式**。效力层级见 `team-charter.md` §1.0（本格式属约定层，非机械门禁）。**默认用最小格式**；早期版本的 ELI10、优缺点字数、10 分制完整性评分、`Net` 总结等格式负担**已取消**。

## 1. 最小格式（默认）

```
D<N> — <一句话问题>
- 选项：A … / B …（或开放提问）
- 建议：<推荐项> —— <一句话理由>
- 选错代价：<一句话；无实质代价写「无」>
- 回复方式：直接回 A / B 或自由文本
```

**判档**：自问「选错了会坏什么」——答不出具体代价 → 用上面的最小格式；答得出 → 补一节「风险与备选」，**仍不要求评分、字数或固定段落**。需要解释背景时用一句话说明，不写 ELI10 段落。

## 2. 编号与确认收束

- 一次会话内第一问为 `D1`，自己递增；多角色并行加角色前缀（`D-PM-1`、`D-ARCH-1`）防用户回复歧义。
- **不可逆 / 破坏性操作**（删除、强推、覆盖、清库）须要求用户**显式输入**选项字母或确认词，写明「什么不可逆」；含糊回复（「好的」「可以」「嗯」）与静默一律**视为未确认**，重新追问。
- **未响应收束**：发出确认后停止等待，转 `NEEDS_CONTEXT` 报项目经理（附问题原文与已尝试内容），**不阻塞其他分片**；PM 汇总为一次批量决策请求（charter §1.5）。**不无限等待、不自行猜答案替代确认。**

## 3. 工具不可用时的降级

提问工具不可用时用散文呈现同样的三要素（选项 / 建议 / 选错代价），列出可用回复，发出后停止等待。

## 4. 与流程档位的关系

- **微项目 / 标准档**：一律最小格式；**阶段级批量授权**代替逐任务确认（charter §9）。
- **完整档**：方向性决策可补「风险与备选」一节，但格式要求不回到旧版全格式。
- 生产版放行的**唯一真人签字点**见 charter §8，不走本简报的多次确认。

## 5. 已删除的格式负担（不再要求）

ELI10 段落、优缺点逐条 ≥20 字、完整性 10 分制、`Net:` 总结、选项超过 4 个强制拆分、散文降级时强制携带评分。这些是**形式要求**，机械不可判定，套在大量确认点上只增加交互成本，对 AI 会话无收益。各角色特有的反模式仍保留在对应 skill 的「常见错误」中。
