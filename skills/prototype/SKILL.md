# 原型生成（prototype）

## 目的

在系统需求分析阶段，做出系统的界面原型，展示给用户。

## 执行者

`product-manager`

## 输入

- `docs/prd/overview.md`、各组件/模块 `ba.md`、`prd.md`

## 输出

- `pages/prototype/$COMPONENT/`（组件原型文件，页面文件名用 snake_case）
- `pages/prototype/$COMPONENT/index.md`（组件页面索引：页面 → 文件 → 关联 FR）

## 交付形态（按复杂度选择）

1. **轻量**：单页 HTML（内联 CSS，无构建），可静态打开预览。
2. **说明式**：Mermaid 页面流转图 + 每个页面的元素清单（表格式线框描述）。
3. **可交互**：多页 HTML + 简单 JS（仅当需求要求交互确认时）。

> 默认优先轻量单页 HTML，避免为原型引入构建链。

## 要求

- 覆盖需求中的主要界面（登录、列表、表单、详情等），**按组件建目录**，页面文件与索引同目录。
- 每个界面标注服务的功能编号 `fr-$COMPONENT-$MODULE-NNN`。
- 明确**交互流程**（页面流转，Mermaid）。
- 只做原型，不实现真实逻辑（不接后端）。
- **每个页面根元素必须标 `data-fr`**（`data-fr="fr-a-b-001,fr-a-b-002"`，逗号/空格分隔）：这是页面与 FR 的唯一机器可读关联。`docs/prd/RTM.md` §2「页面 × FR」矩阵由 `scripts/gen_docs.py` 扫此属性派生，**不再手写矩阵**。
  - 页面无 FR 承接 → 要么补 FR，要么删除该元素；确需保留时在该元素标 `data-fr-unmapped="理由"`，RTM 会把它列为未挂项（可见可审，不掩盖）。
  - 原型定稿后跑 `python scripts/gen_docs.py --root . --type rtm` 刷新 RTM。
- **职责边界**：原型表达 L4（长什么样、怎么走）——按钮态、文案、动效、布局在此呈现；**业务规则不在原型自定义**，一律引用（占位符）。

## 检查清单

- [ ] 覆盖主要界面
- [ ] 组件目录与 `index.md` 页面索引已产出
- [ ] 界面标注功能编号
- [ ] 每个页面根元素已标 `data-fr`；已重跑 `gen_docs.py --type rtm` 且 §2 无「未挂 FR」
- [ ] 页面流转图齐备
- [ ] 已展示给用户确认

## 触发与边界

**该用**：需求阶段让用户"看见"界面，尽早对齐预期。

**不该用**：
- 真实前端实现（接口调用、状态管理）→ 属 ui-developer 编码任务
- 只做静态展示不需要交互 → 说明式线框 + Mermaid 亦可

## 常见错误

- 原型接后端/写真实逻辑（原型只表达"长什么样、怎么走"）。
- 界面不标功能编号，无法与需求对齐。
- **页面元素丰富但无 FR 承接**（页面 × FR 矩阵空白却照常交付——历史上曾出现"原型丰富、PRD 功能点缺位"的失配）。
- **在原型里自定义业务规则**（应引用后台 PRD 的占位符）。
- 为原型引入构建链（默认优先零构建单页 HTML）。
