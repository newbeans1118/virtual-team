# 通用设计（general-design）

## 目的

在全局架构与数据库设计确定后，产出**组件级功能设计**（含算法与日志事件）、**组件接口**，以及**全局接口契约与日志规范**。

## 执行者

`architect`

## 输入

- `docs/prd/$COMPONENT/$MODULE/prd.md`（按组件/模块）
- `design/ARCH.md`、`design/DATABASE.md`

## 输出

| 文件 | 层级 | 内容 |
|------|------|------|
| `design/INTERFACE.md` | 全局 | 横切契约（版本/兼容/幂等/分页/限流/超时/重试/熔断/错误分类/租户）+ 组件接口索引 |
| `design/LOGGER.md` | 全局 | 日志格式/目录/级别/脱敏/保留（**不写模块事件**） |
| `design/$COMPONENT/interface.md` | 组件 | 对外接口 + 跨模块接口 + 模块内接口（模版 `templates/INTERFACE-COMP.md`） |
| `design/$COMPONENT/func.md` | 组件 | 功能设计 + FR 映射 + 算法 + 日志事件（模版 `templates/FUNC.md`） |

**FUNC 拆分规则**：组件 FR > 12 条，或 `func.md` > 300 行 → 按模块拆为 `design/$COMPONENT/$MODULE/func.md`；**拆分后不再保留组件级 func.md**（禁止双写）。

## 内容要求

### 全局 INTERFACE.md
- **横切契约**：版本/兼容/幂等/分页/限流/超时/重试/熔断/错误分类/认证与租户（全局统一，组件不得各自另立）。
- **组件接口索引**：组件 → `design/$COMPONENT/interface.md` → 接口数量；索引必须与实际组件一致。
- 具体接口**不在本文件展开**，避免单文件膨胀。

### 组件 interface.md
- **对外接口**：REST/RPC/消息，含路径、方法、请求/响应 schema、错误码、认证、幂等、超时、重试。
- **跨模块接口**：提供方/调用方模块、签名、参数、返回、异常。
- **模块内接口**（可选）：仅需跨开发者约定时填写。
- 每个接口标注服务的功能编号。

### 组件 func.md
- **组件信息**：组件、模块清单、FR 数量、是否按模块拆分。
- **FR → 设计条目映射**：逐条 FR 对应章节；未覆盖须在“追溯与缺口”写明理由。
- **功能设计**：功能说明、依赖、接口引用、异常路径、处理流程（Mermaid）。
- **数据结构与算法**（按需）：仅复杂功能（影响多组件或含并发/事务一致性），给选型、伪代码、复杂度、边界。
- **日志事件**：事件、级别、关键字段、脱敏、说明——格式规范引用全局 `LOGGER.md`，不重复。
- **模块交互**：组件内模块调用关系。

### 全局 LOGGER.md
- 日志目录、文件构成、格式（字段/时间/级别）、脱敏规则、保留期。
- **不写各模块事件清单**（在对应 `func.md` §5）。

## 质量要求

- 所有设计可追溯到功能编号；无对应功能的接口/结构不写。
- 接口契约完整，异常路径与错误码必须定义。
- 全局横切契约只有一份，组件接口不得与之冲突。
- 日志不得记录敏感信息明文。

## 检查清单

- [ ] 全局 INTERFACE 含横切契约与组件接口索引
- [ ] 每个组件有 interface.md 与 func.md（或按模块拆分的 func.md）
- [ ] 每条 FR 在设计中有落点；未覆盖已写理由
- [ ] 满足复杂判据的流程有算法设计（在 func.md 内）
- [ ] func.md 含日志事件表
- [ ] 组件接口与全局横切契约一致

## 触发与边界

**该用**：架构与数据库设计确定后，做组件级详细设计。

**不该用**：
- 定架构与选型 → 用 `architecting`
- 设计数据库 → 用 `data-modelling`
- 评审设计 → 用 `design-review`

## 常见错误

- 仍按旧的单文件设计产出（FUNC/算法各一份，已废弃）。
- 组件接口另立一套版本/幂等规则，与全局 INTERFACE 冲突。
- FUNC 拆分后同时保留组件级文件（双写）。
- 接口只写正常路径，不定义异常与错误码。
- 日志记录敏感信息明文（违规）。
- 算法设计不给复杂度与边界条件。
