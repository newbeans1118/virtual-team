# PRD 评审（prd-review）

## 目的

评审业务分析说明书与 PRD 的质量，确保需求完备、准确、一致、可追溯。

## 执行者

`prd-reviewer`（评审人另含**用户**）

## 输入

- `docs/PROJ_$PROJECT_NAME.md`
- 全局：`docs/prd/overview.md`、`prd-nonfunc.md`、`dict.md`
- 本组件：`docs/prd/$COMPONENT/**/biz.md`、`prd.md`（含 `prd-ui.md`/`prd-svc.md`）

## 输出

- **按组件**：`review/prd/RV-PRD-$COMPONENT-xxx.md`（由 PM 汇总全部组件结论）

## 评审角度（10 项，逐项给结论）

1. 业务流程准确性、合理性，能否达到业务目标
2. 业务功能定义完备性，是否满足业务运行实际要求；每条 FR 是否标了优先级 `M/S/C` 与「关联裁定」；**「处理逻辑」是否经四问检验**（判定条件/计算规则/状态迁移/数据落点），是否只有"调用接口后返回结果"一类套话；跨组件 FR 是否有「上游依赖」（输入/时机/降级）；页面索引「状态要求」列是否覆盖真实存在的异常/空态（只写"正常"即判不完备）
3. 数据字典完整性，业务实体状态变化合理性
4. 业务需求一致性，是否存在矛盾
5. 业务模块划分合理性（高内聚、低耦合）
6. 非功能需求合理性（不遗漏、不过分）
7. 冗余、低价值需求筛查
8. 角色 / 业务流程 / 实体 / 功能 / 数据字典之间的相互关联合理性
9. **验证条件（acceptance）完备性**：每个功能点的 acceptance 是否按生成清单（正常/边界/异常/权限校验/输入校验/状态约束）逐类对照？适用类别是否被遗漏？每条条件是否**GWT 化且可判定**？不适用类别的省略是否给了理由？
10. **跨产物一致性**：是否产出「页面 × FR 覆盖矩阵」（并入 RTM）？原型每个页面/主要操作是否挂到 ≥1 条 FR（或占位符）？**矩阵有空白即不通过**；FR 粒度是否经五条检验（无「以及/同时还要」复合、无多个不相干 when、无 L4 细节混入）；前后台边界是否清晰（前台不自定义业务规则）；**排除项是否写了归属去向**；**占位符是否登记进 §7.3 回填清单且每项有当前假设/责任人与回填位置**（只写"待补充"= 死链）；**占位符与 §7.3 回填清单是否双向一致**（跑 `verify_artifacts.py` 的 `prd-status` 规则：未登记 / 幽灵登记都会 FAIL）；需求状态标注是否正确（`gated` 允许未清零 / `closed` 必须为 0，且无"永久占位"）。

## 报告格式

| 字段 | 说明 |
|------|------|
| 问题编号 | `RV-PRD-$COMPONENT-xxx-NN` |
| 级别 | P0 / P1 / P2 |
| 评审角度 | 1–10 |
| 位置 | 文件 + 章节（biz-xxx / fr-xxx / 实体） |
| 问题描述 | 具体 |
| 修改建议 | 可执行 |
| 责任角色 | product-manager 等 |
| 状态 | 待处理 / 已修复 / 已关闭 |

附**总体结论**：通过 / 不通过（列出阻塞 P0/P1）。

## 闭环

报告 → 报告项目经理（经 PM 中转给产品经理）→ 修改 → 评审员验证 → 关闭。

## 检查清单

- [ ] 10 个角度逐项覆盖
- [ ] biz ↔ fr 覆盖矩阵已校验
- [ ] **acceptance 完备性已核对**（逐类对照生成清单，漏类/不可判定条件已指出）
- [ ] **跨产物一致性已核对**（页面 × FR 覆盖矩阵无空白；FR 粒度经五条检验）
- [ ] **范围与契约已核对**（优先级 M/S/C 与关联裁定齐全；处理逻辑四问齐全、非套话；跨组件有「上游依赖」；排除项有归属；页面状态要求无空缺；占位符条数与 §7.3 一致且状态标注正确）
- [ ] 结论明确（通过/不通过）
- [ ] 问题闭环

## 触发与边界

**该用**：PRD 完成、进入 PRD 评审门禁时。

**不该用**：
- 评审设计/数据模型 → 用 `design-review` / `datamodel-review`
- 评审代码 → 用 `code-review`
- 评审项目整体可行性/验收 → 用 `accepting`

## 常见错误

- 只挑文字问题，不校验 biz ↔ fr 追溯（漏检缺功能）。
- **不核对 acceptance 完备性**（漏检"只写正常路径、漏边界/异常/权限"这类需求缺陷）。
- **只查文档内部结构，不做跨产物对账**（漏检"原型页面丰富但 PRD 功能点缺位"的失配——页面 × FR 矩阵有空白却不拦）。
- 结论模糊，不给"通过/不通过"。
- 报告问题不给位置与责任角色，无法闭环。
