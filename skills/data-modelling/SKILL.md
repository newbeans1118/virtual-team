# 数据库设计（data-modelling）

## 目的

设计数据库：全局数据规范 + 按组件落地的表结构、索引、DDL，产出可执行、与数据字典一致的数据库设计。

**分层原则**：所有组件共用的（命名/主键/审计字段/字符集/安全分级）写全局；只属于一个组件的（表/字段/索引/DDL/迁移）写组件。目的是让读者只读本组件那一份，不需要加载全部表。

## 执行者

`architect`

## 输入

主输入为已定稿的 PRD 产物：

- `docs/prd/dict.md`（数据字典）
- `docs/prd/$COMPONENT/$MODULE/prd.md`
- `docs/prd/prd-nonfunc.md`（性能指标影响索引设计）

也接受四类直接输入，按同样流程落到设计文档：① 自然语言业务描述；② 现有 DDL / ORM 模型（重构或扩展）；③ 业务规则列表；④ 上述混合。缺 PRD 时先反推实体与关系再向下走，但不跳过数据字典一致性校验。

## 输出

- **全局概览** `design/DATABASE.md`：组件数据索引、数据设计原则、**全局数据规范**、跨组件 ER、跨组件引用与约束、安全分级
- **组件明细** `design/$COMPONENT/database.md`：组件内 ER、表清单、表结构、索引、DDL、生命周期、敏感字段、迁移演进

## 内容要求

按 **概念 → 逻辑 → 物理 → 复核** 组织，落在「全局 + 组件」两层：概念＝ER 与跨组件引用，逻辑＝全局规范与表结构，物理＝DDL 与索引，复核＝质量 / 反模式 / 优化建议（见 §质量要求、§常见错误）。

### 全局 `DATABASE.md`

0. **组件数据索引**：组件 → 文件 → 表数量 → 主要实体 → 章节锚点（读者第一入口）。
1. **数据设计原则**：范式取舍、何时反范式、主键/外键总体策略。
2. **全局数据规范**：命名、主键类型、审计字段、字符集与时区、软删、金额精度、枚举、空值策略——组件文件不重复声明。
3. **跨组件 ER**：只画跨组件关系；无则写明"各组件数据独立"。
4. **跨组件引用与约束**：引用方.表 → 被引用方.表、删除策略、外键策略（物理 vs 应用层）、跨组件事务与补偿。
5. **全局安全策略**：敏感数据分级（L1–L4）与处理要求。

### 组件 `database.md`

1. **组件内 ER**：只画本组件。
2. **表清单**：表 → 模块 → 说明 → 对应实体 → 关联功能编号。
3. **表结构详述**：字段/类型/允许空/默认值/约束/说明。
4. **索引设计**：索引名、类型、字段、支撑的查询/功能编号。
5. **DDL**：完整可执行（含约束、注释），与 §3/§4 逐字对应。
6. **数据生命周期**：增长量级、软删/归档、保留期、清理方式。
7. **敏感字段**：字段 → 级别（引用全局 §5）→ 处理方式。
8. **迁移与演进**：expand-contract 四阶段、验证、回滚、大表策略（见 `templates/DATABASE-COMP.md` §8）。

## 硬性约束

| 约束 | 要求 |
| --- | --- |
| ❌ 自然主键 | 不用身份证 / 邮箱 / 手机号等做 PK，改用自增 ID 或 UUID |
| ❌ 超宽表 | 单表字段 > 40 个必须垂直拆分 |
| ❌ 伪关联 | 不用逗号分隔或 JSON 数组代替关联表；确需反范式须写明性能依据 |
| ✅ 时间戳 | 每表 `created_at` / `updated_at`（TIMESTAMP），用户明确反对除外 |
| ✅ 外键索引 | 所有 FOREIGN KEY 列显式建 INDEX |
| ✅ 约束命名 | `fk_` / `uq_` / `idx_` / `pk_` 前缀显式命名，不用系统生成名 |
| ✅ 注释 | 表与关键字段带 COMMENT，语言与用户一致 |
| ✅ 字典一致 | DDL 与 `dict.md` 一一对应，不凭空加字段 |

## 质量要求

- DDL 与数据字典字段一一对应，不凭空加字段。
- 每个索引必须说明它服务于哪些查询/功能编号。
- 范式适用为度：不过度规范化也不冗余失控。
- **全局与组件不重复**：全局已声明的规范，组件文件只引用不复制（防两处漂移）。
- **跨组件外键必须出现在全局 §4**：组件文件里出现的跨组件引用，全局必须有对应行；否则视为不一致。
- **图形一律 Mermaid**（`erDiagram`），不引入 DBML 或其它格式，保证单一可版本化来源。

## 检查清单

- [ ] 全局 `DATABASE.md` 含组件数据索引 + 全局数据规范 + 跨组件引用约束
- [ ] 每个组件 `database.md` 齐全，且不重复全局规范
- [ ] ER 图齐备（组件内 + 跨组件）
- [ ] DDL 可执行
- [ ] 索引有依据，且所有外键列已建索引
- [ ] 约束显式命名、时间戳齐全、表与关键字段有 COMMENT
- [ ] 字段与数据字典一致
- [ ] 敏感字段级别与处理方式明确
- [ ] 存量/跨版本变更已给迁移与回滚方案（或写不适用理由）

## 触发与边界

**该用**：需要落地数据存储结构时。

**不该用**：
- 定义业务实体语义 → 用 `prd`（数据字典）
- 设计整体架构 → 用 `architecting`
- 专项评审数据模型 → 用 `datamodel-review`

## 常见错误

- DDL 字段与 `dict.md` 不一致（凭空加字段）。
- 索引无查询依据，或堆冗余索引影响写性能。
- 金额/时间/枚举的字段类型与精度选错。
- 敏感字段未落实加密/脱敏。
- **把全局规范复制进每个组件文件**（规范一改就要改 N 处，必然漂移）。
- **跨组件外键只写在组件文件里**，全局 §4 缺失（评审据此判 P1）。

## 需求不清与异常

- **实体 / 关系 / 主查询场景不明**：先反问，不猜着建——① 核心实体有哪些？② 关系基数（1:1 / 1:N / M:N）？③ 最高频查询？
- **输入含反模式**（JSON 数组字段、无主键、超宽表）：指出违反的范式并给出拆分方案，再继续。
- **单表预估 > 500 万行或 > 10GB**：给 RANGE 等分区策略，写入组件 `database.md` §8；DDL > 200 行先出核心表并询问是否分段。
