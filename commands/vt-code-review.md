> 派发按 charter §5 说明 2b：**经 PM 派发**；评审员无消息通道，问题一律**报 PM 中转**，不得直接发送给责任角色。

委派 **code-reviewer** agent 执行**代码评审**。

> **按档位（discipline §2 / charter §9）**：**完整档**两阶段独立评审、顺序不可颠倒；**标准 / 微项目档**合并为**一次全量评审、一份报告**，报告内分「规格符合性」「代码质量」两节分别给结论（检查项不减）。AI 评审＝自检，不是独立审核（charter §4）。

> **缺陷修复评审**：P0/P1 修复后以 BUG 编号 + fix commit 为输入，走**单阶段修复评审**（五项检查，见技能同名小节），结论回填 `BUG.fix.review`。

## 要求

1. 读取 `rules/team-charter.md`、`rules/engineering-discipline.md`、`docs/prd/`、`design/`、`src/`。
2. 使用 `code-review` 技能：完整档**先做阶段一规格符合性**（功能编号是否全实现、有无多做/漏做），**再做阶段二代码质量**（正确性/质量/安全/性能/可维护）；标准 / 微项目档按合并档**一次评审覆盖两节**。
3. 产出报告 `review/code/CR-CODE-xxx.md`，每个问题须标注**文件 + 模块 + 功能编号**，并分级 P0/P1/P2；**两节分别给结论**（完整档 = 两阶段各自结论）。
4. 问题**报告项目经理**，由 PM 派发责任工程师修订；修订后由 PM 转回评审员验证并关闭，形成闭环（评审员无消息通道，不得直接发送）。

## 禁止

- **除自身评审报告外，只读代码不得修改**（必要时可运行验证，但不得改动被评审物）。
- 禁止跳过规格符合性、只评代码质量。
- 禁止只报告不跟踪。

## 档位裁剪（判据与不可裁红线见 charter §9；档位读 `board/KANBAN.md` 首行，未定档按标准档）

- **微项目 / 标准（默认）**：**一次全量评审、一份报告**，内分「规格符合性」「代码质量」两节分别给结论（discipline §2）。
- **完整**：两阶段独立评审、顺序不可颠倒。
- 任何档位都保留 P0/P1 缺陷修复的单阶段修复评审。
