委派 **release-engineer** agent 执行**生产版发布**（阶段二）。

> 测试版构建（阶段一）在代码评审闭环后进行，由 PM 在进入测试阶段前派发，不走本命令。

## 前置（硬性）

- 项目验收评审已通过（`review/project/RV-PROJ-ACCEPT.md`）。

## 要求

1. 读取 `rules/team-charter.md`、`design/`、`test/report/`、验收结论。
2. **四方联合确认**：产品经理、测试经理、架构师、代码评审员。
3. **构建决策**：测试期无代码变更 → 测试版构建直接升级标记为生产版；有变更 → 重新构建（全新 worktree 从主干）再确认。
4. **发布计划**：按 `templates/RELEASE-PLAN.md` 产出 `release/RELEASE-PLAN-<version>.md`（部署策略/DB 迁移顺序/回滚/发布后验证）。
5. **制品完整性**：生成 `SHA256SUMS` 与 `sbom.json` 并归档。
6. **回滚演练**：生产版发布前在测试环境执行一次回滚，记录结果；未演练不得发布。
7. **打 tag 并部署**：`git tag` 打在主干 commit 上，按计划执行（含 DB 迁移顺序）。
8. **发布后验证**：≥30 分钟窗口检查错误率 / P95 / 关键业务量（阈值取自 `design/ARCH-NFR.md` §4），超阈值回滚并记录。
9. 发布组件可复现：记录版本、commit、构建命令、依赖版本；产出发布说明交付用户。

## 禁止

- 验收未通过，禁止生产版发布。
- 未经四方联合确认，禁止标记为生产版。
- 禁止在脏工作区直接构建。
- 禁止无发布计划、无 SBOM/校验和、未演练回滚就发布生产版。
- 禁止跳过发布后验证窗口。
