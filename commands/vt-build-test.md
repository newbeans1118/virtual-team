> 派发按 charter §5 说明 2b：**经 PM 派发**；评审员无消息通道，问题一律**报 PM 中转**，不得直接发送给责任角色。

委派 **release-engineer** 执行**测试版构建**（`releasing` 技能阶段一）。

## 前置（缺一 → BLOCKED 报 PM）

- 全部开发任务的代码评审已闭环（无未关闭 P0/P1）。
- 主干含全部通过代码评审的任务 commit（`git log` 可查）。

## 要求

1. 读取 `rules/team-charter.md`、`design/ARCH.md`、`review/code/` 结论。
2. 按 `skills/releasing` 阶段一执行：
   - **全新 worktree** 从主干拉取构建（禁止用工作区脏状态）
   - 编译 → 打包归档 `release/artifact/`（含版本号、commit、依赖清单）
   - **制品完整性**：生成 `release/artifact/SHA256SUMS` 与 `sbom.json`；**无真实构建环境时**只列出待执行的生成命令与目标产物，标注「待人工执行」，不得填写编造的校验和或依赖清单
   - **发布计划草案**：按 `templates/RELEASE-PLAN.md` 产出 `release/RELEASE-PLAN-DRAFT.md`（部署策略 / DB 迁移顺序 / 回滚方案 / 发布后验证窗口与阈值；§1 的用户放行与 tag 留空，待生产版发布时补齐；**须含「人工执行回执」节**）
   - 用 `skills/doc-writing` 产出 `release/manual-install.md` / `release/manual-release.md`（**基于真实构建产物与上述草案**；无真实产物时须在手册中标注「待人工执行」）
   - 目标环境部署 + 冒烟验证（记录命令与结果；**无目标环境时记录待执行命令并标注「未执行」**，不得编造结果）
   - **回滚演练**：在测试环境对本次构建执行一次回滚，产出 `release/ROLLBACK-DRILL.md`（时间 / 环境 / build 标识 / 回滚命令 / 结果 / 判定人；**无测试环境时只登记待演练项与判定人，结果留空，不得写「已通过」**）
   - 标记**测试版**
3. 产出**构建证据**：build 标识 / commit / 构建命令 / 依赖版本 / 冒烟结果 / 手册路径 / 制品校验和 / 草案与演练记录路径——交 PM 记入看板，供 `RUN.envs` 与项目验收引用。**每项须如实标注「已执行 / 待人工执行 / 未执行」，不得把待执行项写成已完成。**
4. 向 PM 报告：`BUILD-DONE | build | commit | 冒烟结果 | 手册路径 | 草案路径 | 演练记录路径`；失败报 `BUILD-BLOCKED | 原因 | 已尝试`。

> **时序约束**：发布计划草案、制品校验和、回滚演练记录**必须在测试版构建阶段产出**。项目验收（`/vt-accept`）要读它们，而生产版发布（`/vt-release`）在验收通过之后；把这些证据留到发布阶段会造成验收↔发布循环死锁。

## 证据效力与人工回执（必读）

本插件运行在 AI 会话中，通常**不具备真实 CI/CD、部署环境与监控**。因此：

- 上述 `SHA256SUMS`、`sbom.json`、冒烟结果、`ROLLBACK-DRILL.md`、build/commit/时间戳等，**若由 AI 生成，只是「待人工执行清单」的记录载体，不具备发布效力**，不得被当作「已真实执行」的证据，也不得据此宣称可发布。
- 真实执行由具备环境的人（用户 / 运维 / CI）完成，并在 `release/RELEASE-PLAN-DRAFT.md` 的「人工执行回执」节登记：**执行人 / 时间 / 实际命令 / 输出摘要 / 结论**。回执是唯一具备发布效力的证据。
- 无回执时，验收阶段只能判定「材料齐备、缺口已列明」，**不得判定「已验证可发布」**；评审结论须显式标注「AI 产物，未见人工回执」。
- 机械校验（`scripts/verify_artifacts.py`）**不扫描 `release/`**，不为这些文件盖章；格式合规 ≠ 事实成立。证据真实性只能靠人工回执，机械校验无解。

## 禁止

- 禁止跳过冒烟验证（无环境时须如实登记「未执行」，不得伪造结果）。
- 禁止在 P0/P1 未关闭时构建（测试结论会失真）。
- 禁止用工作区而非 worktree 构建。
- 禁止修改 `src/` 代码（构建发现问题 → 报 PM 派发开发者修复）。
- 禁止把发布计划草案、制品校验和、回滚演练推迟到生产版发布阶段。
- 禁止编造校验和、依赖清单、冒烟结果、回滚演练结论或任何执行时间戳。

## 档位裁剪（判据与不可裁红线见 charter §9；档位读 `board/KANBAN.md` 首行，未定档按标准档）

- **微项目**：发布后验证窗口可免（写理由）；人工执行回执要求不降。
- **标准（默认）**：保留验证窗口；草案 / 校验和 / 演练记录照常产出。
- **完整**：≥30 分钟窗口 + 完整人工回执。
- 任何档位都不得把 AI 生成的证据当作已真实执行（见「证据效力与人工回执」）。
